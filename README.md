# ITDesk

Приложение заявок технической поддержки с основной базой MongoDB и встроенной обработкой данных. Заявки, пользователи, комментарии и история хранятся в MongoDB; Pandas, Spark, Spark SQL, Hadoop Streaming и Matplotlib запускаются кнопками из окна приложения.

## Запуск

На подготовленном компьютере дважды нажмите `start.bat` либо выполните:

```powershell
python run_app.py
```

Откроется окно входа. Подготовленные аккаунты: `admin/admin123`, `tech/tech123`, если пароли не менялись. Запуск подключит MongoDB, один раз перенесёт старые данные из `itdesk.db`, запустит API и клиент. При закрытии клиента созданный этим запуском API остановится; MongoDB остаётся работать. Уже запущенный совместимый API используется повторно.

Если остался работающий сервер от старой версии, остановите его в прежнем терминале сочетанием Ctrl+C перед новым запуском.

## Демонстрация

1. Войдите, создайте заявку «Не работает проектор».
2. Выберите строку и нажмите «Документ MongoDB» — увидите настоящий документ из коллекции `tickets`.
3. Откройте заявку, нажмите «Взять в работу» и снова посмотрите документ.
4. Нажмите «Обработка данных». При необходимости добавьте помеченные учебные заявки, выполните импорт API.
5. Нажмите «Выполнить обработку целиком». В том же окне появятся результаты и графики. Ждите завершения; отдельно вводить команды не нужно.

## Установка на другом компьютере

Нужны Python с pip, MongoDB Community, JDK 17, Apache Hadoop 3.5.0, библиотеки проекта. VS Code используется как среда разработки по плану. Установка Python-зависимостей:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe run_app.py
```

Java и Hadoop задаются через `JAVA_HOME` и `HADOOP_HOME`; подготовленные копии `.tools/java` и `.tools/hadoop-3.5.0` находятся автоматически. Для Hadoop на Windows нужны совместимые `bin/winutils.exe` и `bin/hadoop.dll`. На этом компьютере они уже добавлены, настоящий MapReduce проверен. Использована [Windows-сборка сообщества zehelh/winutils для Hadoop 3.5.0](https://github.com/zehelh/winutils/releases/tag/hadoop-3.5.0), SHA256 сверена с метаданными GitHub Release. Это не официальный бинарный релиз Apache.

`.tools` не включается в Git: на другом компьютере установите среды выполнения или перенесите их отдельно. PyQt6, FastAPI и requests сохранены из исходного проекта для интерфейса и связи с API; новые средства хранения и обработки соответствуют плану, другие СУБД не требуются. Java — среда выполнения Hadoop и Spark.

## Данные и настройки

Настройки MongoDB находятся в секции `[mongodb]` файла `config.ini`. По умолчанию адрес `mongodb://127.0.0.1:27017`, рабочая база `itdesk`. Переменные `ITDESK_MONGO_URI` и `ITDESK_APP_DB` переопределяют адрес и имя базы.

- `users` — пользователи и хеши паролей;
- `sessions` — сеансы входа;
- `tickets` — заявки со встроенными комментариями и историей;
- `external_raw` — исходные ответы внешнего API;
- `processing_jobs` — состояние задач обработки;
- `counters` — выдача числовых ID;
- `migrations` — отметка переноса старой базы.

Старая SQLite читается только при однократном переносе и сохраняется как резервный исходный файл. Новые заявки в неё не записываются. Перенос сохраняет ID, пользователей, хеши паролей, комментарии и историю; при конфликте идентификаторов останавливается, не заменяя рабочие документы. Сессии старой версии не переносятся — нужно войти заново.

Рабочие и учебные заявки отличаются полем `source`. Учебные и импортированные записи видят сотрудники; обычный пользователь видит только свои. Повторный импорт не сбрасывает изменённые вручную статусы. Удаление заявки сотрудником удаляет документ вместе с его комментариями и историей; в интерфейсе есть подтверждение.

Каждая обработка получает отдельную папку `analytics_data/runs/<id>`. Результаты относятся к снимку заявок на момент запуска. Поддерживается один процесс API на базу. Одновременно выполняется одна задача; после перезапуска сервера прерванная задача отмечается ошибкой и может быть запущена снова. Графики обновляются после повторного запуска обработки.

## Проверка и обслуживание

```powershell
python -m pytest -q
python healthcheck.py
python manage.py passwd admin
python manage.py role student tech
python -m analytics.stop_mongo
```

Для тестов нужна доступная MongoDB; тесты создают и удаляют только собственные базы с уникальными именами `itdesk_test_*`. Полный интеграционный сценарий также использует интернет, Java, Spark и Hadoop. Встроенные роли и права проверяются на сервере.

Скрипты `run_server.py`, `run_client.py` и прежние низкоуровневые команды аналитики остаются для разработки. Основной способ запуска для пользователя — `start.bat` или `python run_app.py`. Старая сборка `build.py` относится к предыдущему варианту приложения и не является проверенным способом упаковки нового запуска.
